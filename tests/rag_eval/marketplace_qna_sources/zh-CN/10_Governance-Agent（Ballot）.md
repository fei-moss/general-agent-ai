## Governance Agent（Ballot）

Governance 是产品域名称；Marketplace、Chat 与后端统一使用 Agent Type `ballot`。下列机制是稳定平台知识。项目名、代币、费率、币种、页面位置和具体治理规则属于动态事实，必须读取当前 Agent context；未返回的数据应明确说明不可用，不得用示例值补齐。

**Q: Governance Agent 是做什么的？**

Governance Agent 把 Agent 份额、固定收益累积、Redeem 时领取空投、治理投票和项目动态放在同一个入口。具体项目、代币、固定 APY 和治理参数必须以当前 Agent context 为准。

**Q: Mint Governance Agent 的份额能得到什么？**

平台机制包含四类权益：按当前 Agent 固定 APY 累积收益、在 Redeem 时领取持有期间累积的空投、按快照规则参与治理投票，以及查看项目动态。份额是持有者钱包里的标准链上代币；具体数值和规则读取当前 Agent context。

**Q: 在 Governance Agent 中，直接拿项目币和换成治理份额，机制上差在哪？**

直接持有项目代币主要保留代币本身的价格敞口，项目币仍在用户钱包里。机制上，参与 Governance Agent 会把项目币 Mint 为受合约规则约束的治理份额，并可叠加固定收益、累计空投、治理参与和项目动态；具体 Agent 是否提供及如何提供这些能力，以当前合约和 Agent context 为准。

**Q: 固定收益率怎么累积？**

固定收益按份额规模、持有时长和当前 Agent 公布的固定 APY 累积。准确费率、开始时间、计算口径和展示位置都是当前 Agent 动态事实，必须从 Agent context 或页面读取。

**Q: 固定收益和空投从哪里来，是否可持续？**

固定收益和空投由对应项目方按该 Agent 公布的规则提供和兑付。合约可以约束数额、节奏和领取条件，但不能替项目方证明资金来源长期可持续；来源说明和可持续性应同时核对当前 Agent context 与项目方公开材料。

**Q: 空投什么时候领，怎么领？**

Governance Agent 的稳定机制是持有期间累积空投，并在满足当前 Agent 的 Redeem 条件时领取。实际领取步骤、到账资产和累积展示位置属于动态事实，必须读取当前 Agent context，不得猜测。

**Q: 提案怎么发起，谁能发起？**

提案发起权由当前 Agent 的治理配置决定，可能是达到门槛的份额持有者，也可能由项目方发起。准确门槛、入口和当前提案必须读取当前 Agent context 或提案页。

**Q: 投票权怎么计算？**

投票资格和权重以提案快照时的份额持仓为基础。精确换算规则由当前 Agent 的治理配置决定，必须读取当前 Agent context，不能默认所有 Agent 都是 1 份额等于 1 票。

**Q: 提案快照怎样决定投票资格，什么时候拍？**

Governance Agent 的提案快照决定该次提案的投票资格和投票权重。快照是某一时刻的份额持仓记录，用来固定该提案的投票资格和权重。快照在提案创建时生成，具体快照时间应在当前 Agent context 或提案页展示；快照后的持仓变化不能被擅自套用到该次投票。

**Q: 怎么投票，投完能改吗？**

用户在提案页选择立场并按产品流程签名提交，投票记录可验证。投票是链上操作，需要按所在网络支付标准网络费（gas）；投票期内能否修改属于当前提案或 Agent 的动态规则，必须读取当前 Agent context。

**Q: 用户投出治理票时会自动获得额外激励吗？**

投出治理票不会自动获得额外激励。治理投票是否有额外奖励不是平台统一常量，任何投票激励都必须读取当前 Agent context；没有返回奖励配置时，只能说明当前数据未提供，不能承诺奖励。

**Q: 提案通过后谁来执行？**

执行方式由当前 Agent 的治理规则决定：可链上执行的事项可能由合约执行，链下事项可能由项目方处理。准确执行主体、状态和进度必须读取当前 Agent context 或提案页。

**Q: 退出治理份额时，锁定期和累计奖励怎么处理？**

Redeem 的可用时间、锁定或提前赎回影响由当前 Agent 的赎回规则决定。持有者退出治理份额时，当前 Agent context 必须说明锁定期和累计奖励的处理，包括本金、已累积固定收益和已累积空投；缺失字段不能编造。

**Q: 本金如何保管，项目方能动用吗？**

Mint 进去的本金不会进入项目方个人钱包，而是走合约托管路径；份额和 Redeem 规则由合约约束。项目方不能像处分自有钱包余额一样自由转走持有者本金；准确权限仍应以当前合约为准。

**Q: 在 Governance Agent 中，快照后赎回份额，会不会让已提交的治理票失效？**

投票后可以按当前 Agent 规则申请 Redeem。赎回会销毁相应治理份额，并结束这些份额之后的投票权；不能同时保留已赎回本金和对应份额的未来投票权。快照通常固定资格与权重，但是否在 Redeem 后继续计票必须读取当前 Agent context 或提案规则，不能把示例口径当成所有 ballot Agent 的事实。

**Q: 固定 APY 以后会变吗？**

Governance Agent 的固定 APY 在发起时设定并公开，由合约规则执行；持仓上限和 Redeem 条款也按发起时公开的合约规则执行，不应对已经进入的持有人追溯改写。回答具体 Agent 时仍要从当前 Agent context 读取实际费率、上限和条款，不能使用示例值。

**Q: 收益和空投以什么代币发放？**

固定收益币种和空投代币由当前 Agent 配置决定，并可能不同。必须读取当前 Agent context；未返回币种时应明确说明不可用，不能根据项目名或示例推断。

**Q: 项目方持有很多份额时，投票会不会被操纵？**

Top Holders 用于公开展示份额集中度，让用户在投票前查看权力分布。是否存在项目方投票限制或其他抗集中规则属于当前 Agent 动态事实，必须读取当前 Agent context，不能替项目方判断意图。
