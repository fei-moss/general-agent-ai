## 治理投票与收益细节

本篇 `ballot` 文档只说明提案页结果、治理与交易份额的价格对比及项目上线价值。治理持有者机制归《Governance Agent（Ballot）》；项目、代币和固定 APY 数值必须读取当前 Agent context。

**Q：我的投票权是怎么算的？**

按提案创建时的持仓快照计算，不是按你投票那一刻的持仓。

**Q：提案已经开始了，我现在 Mint 还能投这个提案吗？**

不能。快照在提案创建时就已经固定，之后的持仓变化不影响本次提案的投票权。

**Q：页面显示我有 0 票，提示这个提案的快照没有记录到我的持仓，是什么意思？**

说明快照时间早于你获得份额的时间。可对照提案页记录和份额取得时间。

**Q：临时买入大量份额可以左右投票结果吗？**

不能。投票权取自提案创建时的快照，提案发布之后再增持不产生任何投票权。

**Q：一个提案有哪些投票选项？**

赞成、反对、弃权三个选项。当前票数显示在提案页，历史提案显示在 Proposal History。

**Q：投票需要付 gas 吗？**

需要，投票是链上操作，按所在网络的标准网络费支付。

**Q：治理 Agent 的收益是怎么来的？**

按固定 APY 计息，奖励由项目方以其代币发放。实际数值读取当前 Agent context。

**Q：奖励什么时候到账？**

在赎回时一并领取，持有期间不单独发放。

**Q：赎回流程和交易 Agent 一样吗？**

流程与交易 Agent 一致：提交 Request Redeem，再到 View history 查看。治理持有者规则仍见《Governance Agent（Ballot）》和当前 Agent context。

**Q：产品对比：治理 Agent 的份额单价会不会像交易 Agent 一样涨跌？**

治理 Agent 的份额单价不会像交易 Agent 一样随交易表现涨跌；它按固定 APY 计息，交易 Agent 的份额单价则跟随管理资产变化。

**Q：我们项目想上一个治理 Agent，怎么申请？**

治理 Agent 目前由 Moss 为项目方定制部署，不支持自助创建。可通过 Moss Telegram 或 Discord 社区联系。

**Q：发起 Governance Agent 对项目方有哪些好处？**

把代币持有者转化为可触达、可投票的参与者。持有者可 Mint 份额、领取项目方披露的奖励，并对链上提案投票。
